# Package map

Where things live and what each part is responsible for. Read against the tree on
2026-10-03. The tree itself is [repository-layout.md](repository-layout.md).

## Backend (`backend/`, Go module `github.com/guided-traffic/cowork/backend`)

| Package | Responsibility | Key symbols |
|---|---|---|
| [`api/`](../../backend/api/) (package `apispec`) | The API document, the contract: `openapi.yaml` and one file per path family under it, `components/`, the oapi-codegen configuration, the bundle `openapi.gen.json` (generated) and `embed.go`, which embeds it ([api.md](api.md#the-document)) | `Document` |
| [`cmd/cowork/`](../../backend/cmd/cowork/) | The binary: `serve`, `migrate`, `version`, `help`. Loads the configuration, migrates as the owner role, checks the database, runs the bootstrap, wires store, event hub, storage, API and server, runs the jobs. `run` is separated from `main` so a test drives it with its own environment and writers | `run`, `runServe`, `runMigrate`, `requireForServe`, `checkDatabase`, `runJobs`; `version`/`commit`/`buildTime` (set by the linker) |
| [`internal/api/`](../../backend/internal/api/) | The API: the pipeline in front of the generated server, and one method of `Server` per operation; file by file below | `New`, `Options`, `Server` |
| [`internal/api/apigen/`](../../backend/internal/api/apigen/) | Generated by oapi-codegen v2.8.0 from the bundle: models, the strict server interface, the registration on the mux, the Go client the tests use. Never edited | `StrictServerInterface`, `HandlerWithOptions`, `ClientWithResponses` |
| [`internal/auth/`](../../backend/internal/auth/) | Who a request acts for: the token's shape and hash (`token.go`), the session cookie's name, value and hash (`session.go`), Argon2id hashing and verification, the password policy and the dummy hash (`password.go`), the username rule (`username.go`), the principal and the agent mark (`principal.go`), the authorization of an act (`authorize.go`) | `GenerateToken`, `HashToken`, `WellFormedToken`, `GenerateSession`, `HashSession`, `SessionCookie`, `HashPassword`, `VerifyPassword`, `CheckPassword`, `DummyHash`, `ValidUsername`, `NormaliseUsername`, `Principal`, `ParseAgentHeader`, `Mark`, `Need`, `Authorize`, `Cap…`, `HardOff…` |
| [`internal/bootstrap/`](../../backend/internal/bootstrap/) | What the configuration says an installation starts with: the local administrator and the bootstrap tenant, kept in step at every start under an advisory lock as `system:bootstrap` ([ADR 0032](../adr/0032-bootstrap-from-helm-values-a-local-administrator-synced-from-a-secret-and-an-init-state-for-administrators-only.md)) | `Sync`, `Params` |
| [`internal/config/`](../../backend/internal/config/) | Every `COWORK_*` variable, its default and its validation, the login's among them (the local administrator, the password policy, the lockout, the sessions, the token lifetimes, `COWORK_BASE_URL` as an origin, `COWORK_TRUSTED_PROXIES` as CIDRs). `Load` takes a lookup with the contract of `os.LookupEnv` and reports every invalid value at once, naming the variable, never a secret's value | `Config`, `Storage`, `Load`, `Origin`, `Env…`, `Default…` |
| [`internal/domain/`](../../backend/internal/domain/) | The vocabularies and the rules that need no database: roles and scopes (`domain.go`), ticket vocabularies, keys, urgency rule set v1, link names (`ticket.go`), the transition matrix and the states an agent closes from (`transition.go`), the three progress stages, what a write of them does to the state and which done is by them (`progress.go`), the rank's keys (`rank.go`), attachment types and file names (`attachment.go`) ([domain.md](domain.md)) | `Role`, `Scope`, `ParseTicketKey`, `FullKey`, `DeriveUrgency`, `UrgencyInputs`, `LinkType.Name`, `ClassifyMove`, `TicketState.AgentCloses`, `Stages`, `EffectOfStages`, `WithdrawalStaysDone`, `DoneByStages`, `RankBetween`, `ValidRank`, `DetectAttachmentType`, `SanitizeFileName` |
| [`internal/events/`](../../backend/internal/events/) | The event hub of one replica: a replay ring per tenant, a filter and a bounded buffer per stream, the per-person limit ([events.md](events.md)) | `Hub`, `New`, `Publish`, `Subscribe`, `SetUp`, `Close`, `Filter`, `Resync`, `Unavailable` |
| [`internal/httpserver/`](../../backend/internal/httpserver/) | The outer handler and the server lifecycle: `/healthz`, `/readyz`, `/api/` handed to the API, a JSON 404 and a 405 for the rest; the request id, the request log, the panic recovery; `Serve` runs until the context ends, runs the shutdown hooks and drains within the timeout | `Options`, `New`, `ListenAndServe`, `Serve` |
| [`internal/markdown/`](../../backend/internal/markdown/) | The canonical Markdown of a ticket, grammar v1, a pure function; golden files in `testdata/` ([markdown-grammar.md](markdown-grammar.md)) | `Render`, `Ticket`, `Question` |
| [`internal/problem/`](../../backend/internal/problem/) | The code catalogue, the one place a problem code is defined, and the RFC 9457 body; `make generate` writes the document's enum and the README table from it | `Code`, `Catalogue`, `Error`, `FieldError`, `New`, `Field`, `Write` |
| [`internal/requestid/`](../../backend/internal/requestid/) | The request id, a UUIDv7, carried through the context | `New`, `With`, `From`, `UUID` |
| [`internal/storage/`](../../backend/internal/storage/) | The attachments' bytes in S3-compatible storage, a minio-go client for one bucket ([storage.md](storage.md)) | `Client`, `New`, `Key`, `Put`, `Get`, `Delete`, `EnsureBucket`, `ErrMissing` |
| [`internal/store/`](../../backend/internal/store/) | PostgreSQL: the pool behind the transaction wrappers, the migrations, the roles check, the list builder, the locks, the jobs, the publication; file by file below ([data-access.md](data-access.md)) | `DB`, `Open`, `Migrate`, `Reader`, `Writer`, `Mutate`, `RunJob`, `Listen` |
| [`internal/store/migrations/`](../../backend/internal/store/migrations/) | The schema, `NNNNNN_<name>.up.sql`, embedded; no down files. `000001_tenants` to `000019_progress_stages` | — |
| [`internal/store/queries/`](../../backend/internal/store/queries/) | The SQL, one file per aggregate: `read/` becomes `readq`, `write/` becomes `writeq` | — |
| [`internal/store/readq/`, `writeq/`](../../backend/internal/store/readq/) | Generated by sqlc ([`sqlc.yaml`](../../backend/sqlc.yaml)). Never edited | `Queries`, one method per named query |
| [`test/fixture/`](../../backend/test/fixture/) | Persons, tenants, memberships, local accounts, projects, tickets and tokens written over the administrative connection, past row-level security; never part of the binary ([testing.md](testing.md#fixtures-of-the-integration-tier)) | `Connect`, `DB.Person`, `Tenant`, `Member`, `Account`, `GlobalAdmin`, `Project`, `Ticket`, `Token`, `TokenSpec` |

| [`tools/problemdoc/`](../../backend/tools/problemdoc/), [`tools/specbundle/`](../../backend/tools/specbundle/) | The generators `make generate` runs first: the problem-code enum and README table; the bundled document | `main` |
| [`sqlc.yaml`](../../backend/sqlc.yaml) | The sqlc configuration: the migrations as schema, `queries/read` → `readq`, `queries/write` → `writeq`, the database enums mapped onto the `domain` types | — |
| [`Containerfile`](../../backend/Containerfile) | Two stages: `golang:1.27.1-alpine` builds the static binary, distroless `static-debian12:nonroot` runs it | — |

### `internal/api`, file by file

| File | Responsibility |
|---|---|

| [`content.go`](../../backend/internal/api/content.go), [`nullable.go`](../../backend/internal/api/nullable.go) | The kept `Accept` header and `wantsCSV`; setting nullable fields explicitly |
| [`me.go`](../../backend/internal/api/me.go) | The person, their tokens — creation included —, revocation, the change of the person's password |
| [`tenants.go`](../../backend/internal/api/tenants.go) | Creating a tenant; the tenant and its settings, members, the audit record (JSON or CSV); the needs `read` and `administer` |
| [`projects.go`](../../backend/internal/api/projects.go) | Projects; `visibleProject`, `projectRole` |
| [`tickets.go`](../../backend/internal/api/tickets.go), [`ticketlist.go`](../../backend/internal/api/ticketlist.go) | A ticket: filing, reading, the key resolver, `PATCH` with its progress stages and the done act or reopen they make (`applyStages`, `stageInputs`, `planStageMove`), the body, the urgency override, the confidential flag, `ticketView`, the stages' refresh; the two lists, their filters and paging |
